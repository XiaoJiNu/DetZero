> 时间：2026-09-03 CST ｜ 模型：qwen3.8flash ｜ 性质：实施方案（未执行命令标注"计划"）
> 前置：`DetZero-nuScenes-HEDNet-qwen3.8flash方案20260831.md` 及其完成报告（S1/S2/S7 脚本、实测数字可复用；Waymo 权重链彻底出局）

## 0. 结论先行

**要"3D 框 + 跟踪 ID + 速度 + score"四个标签、且对齐 nuScenes，最佳路径不是自研，而是：**

```
HEDNet result.pkl（现有，lidar 系，10 类）
  → [N1] detector 输出转 nuScenes tracking json      （~60 行胶水，复用 S1 的 pose 约定）
  → [N2] SimpleTrack 跟踪器（MIT，2021 nuScenes 挑战赛 2Hz 赛道冠军，开箱即用）
  → [N3] SimpleTrack 官方 nuScenes json 输出          ← 这就是交付物
  → [N4] 官方 devkit TrackingEval 出 AMOTA/AMOTP/IDsw（裁决数字）
```

输出即 nuScenes 官方 tracking 提交格式，四个标签原生具备、语义与官方一致：

| 标签 | 字段 | 坐标系/约定 |
| --- | --- | --- |
| 3D 框 | `translation` (x,y,z) + `size` (w,l,h) + `rotation`（四元数） | **global 系**（官方约定，含 ego 运动补偿） |
| 速度 | `velocity` (vx,vy) | global 系（官方 GT 即如此定义）；SimpleTrack 输出 Kalman 平滑后的轨迹速度，**不用 HEDNet 速度头**（实测其角度中位误差 31°，不可信——旧完成报告 §8） |
| 跟踪 ID | `tracking_id` | 每条轨迹稳定 id |
| score | `tracking_score` | detector 置信度直通 |
| 类别 | `tracking_name` | nuScenes **7 类**（car/truck/bus/trailer/barrier… 见 §3 N1），不再折叠 3 类 |

**判定依据（GitHub 调研，全部核实过 license）**：

| 库 | License | 结论 |
| --- | --- | --- |
| **SimpleTrack** (tusen-ai) | **MIT** | ✅ 采用。nuScenes val 2Hz AMOTA 0.687（CenterPoint det），含 per-class NMS、马氏+GIoU 两阶段关联、Kalman 速度平滑——全是按 nuScenes 2Hz 调过的；有现成 nuscenes 输入/输出文档，**零训练、CPU、分钟级** |
| nuscenes-devkit `LidarPointCloudTracker` | MIT（已装） | 备选/下限：官方 tutorial 自带跟踪器，AMOTA≈0.55，简单场合够用 |
| AB3DMOT | CMU 非商用 ❌ | 排除（旧方案 §9 已裁） |
| PF-Track | CC BY-NC-SA ❌ | 排除 |
| centerpoint-baseline (Chiu et al., 2020 冠军) | Apache-2.0 | SimpleTrack 的严格子集，不另上 |
| OGR3MOT / MMOTR / ImmortalTracker | GPL-3.0 ⚠️ / 需训练 / 2D 关联重 | 不进主路线 |

**detector 不动**：HEDNet 框质量已证（3 类口径 mAP 0.743/0.826），跟踪指标天花板在检测端（det→GT 关联率 66%/81%），换 tracker 收益最大、换 detector 是另一件事（后备见 §5）。

## 1. 与旧方案的差异（为什么这次不算造轮子也不绕路）

- 旧 T1/T1-v2 是为绕开"Waymo 权重域差"写的 200 行自研；现在既然放弃 DetZero 3 类合同、直接按 nuScenes 官方格式走，SimpleTrack 的 MIT 实现严格强于自研（冠军级调参 + NMS + 两阶段关联 + 官方 IO 现成）。**T1-v2 退役为对照基线**（数字保留在旧报告 §9）。
- 类别映射从"折叠 3 类"改回 nuScenes 原生 7 tracking 类；traffic_cone 不在官方 tracking 任务内，丢弃（与官方评测同口径）。
- 输出从 pkl 自制 schema 改为 nuScenes json——任何官方/第三方工具直接消费。

## 2. 步骤与命令（计划，未执行）

环境：新建 `conda create -n st python=3.9`（隔离 mv2d 的 pandas2/motmetrics1.4 冲突；SimpleTrack 依赖 numpy/scipy/pandas<2, motmetrics==0.9.9 由 requirements 解决）。数据用 `/data/data/automomous/nuscenes/v1.0-mini`（devkit 原生 dataroot，v1.0-mini 元数据在位）。

**N1** `tools/nustack/export_det_nuscenes.py`（新，~60 行，一次性胶水）
- 输入：HEDNet `result.pkl` + nuscenes info pkl（token 关联，同 S2）；输出 `{token: [ {sample_token, translation, size, rotation, velocity, tracking_name, tracking_score} ]}`——即 devkit 检测 json 格式（global 系：`pose = inv(car_from_global @ ref_from_car)` 已在 S1 对拍为 0 误差，直接复用）。
- 类直通 7 tracking 类；score≥0.1；cone/barrier 丢弃并计数进 manifest。

**N2** SimpleTrack 推理（官方 `docs/nuScenes.md` 路径，2Hz 设置）
- clone `github.com/tusen-ai/SimpleTrack` 到 `/data/code/cv/AutoLabel/third_party/`（固定 commit，记录 sha）；
- 按其 nuscenes 转换脚本吃 N1 json（若其输入仅支持 CenterPoint json 目录结构，写 10 行路径适配，不改其内核）；
- 用其发布的 nuScenes val config（**不改参**——它就是为 nuScenes 2Hz 调的，这是本方案与旧 Waymo 域差教训的本质区别）。

**N3** 输出：SimpleTrack → `tools/nuscenes_result_creation.py` 官方脚本 → `track_results.json`。附加派生一份逐帧 pkl（帧内附 `track_ids (N,)` 列，方便可视化/下游），由 ~30 行转换器生成，不新增格式发明。

**N4** 评估：devkit `TrackingEval`（mini_val）出 AMOTA/AMOTP/MOTA/IDsw/fragments/mt/ml **7 类逐类**；同口径跑三份对照：
1. HEDNet 框 + LidarPointCloudTracker（官方下限基线）
2. HEDNet 框 + SimpleTrack（主路线）
3. 其 CenterPoint 发布检测 + SimpleTrack（论文数字复现，证明 N1 无损）
旁路沿用 S7 `eval_nus_vs_gt.py` 的 mAP（G3'：SimpleTrack 后 ≥ detector − 0.02）。

## 5. 明确不做（以及何时才做）

- **不重训 detector**（HEDNet 已推理完毕）。仅当 N4 数字显示跟踪质量被检测卡死且需要发正式标签时，候选升级 = OpenPCDet StreamPETR/CenterPoint nuScenes 预训练权重推理（Apache-2.0，推理 CPU/GPU 各半天，属加测不属本方案）。
- 不上相机 ReID / 学习特征（SimpleTrack 纯几何，够 2Hz mini；要解决遮挡串 ID 再议）。
- 不做 CRM/GRM/PRM 及任何 Waymo 权重路径（永久出局）。

预计工作量：半天胶水 + 半天环境/复跑 + 半天数字表 ≈ **1~1.5 个工作日**。
